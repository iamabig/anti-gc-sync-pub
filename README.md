# anti-gc-sync-pub (AGS)

**여러 AI 코딩 에이전트가 한 레포 안에서 같은 기록으로 소통하며 동시에 일하게 하는 공통 규격** · MIT

> **gc** = 처음 함께 만든 두 에이전트 **G**emini(Antigravity)와 **C**laude.
> 하지만 AGS는 특정 에이전트용이 아닙니다. 에이전트는 **n개**가 될 수 있고, 각자 코드(예: `CL`, `AG`)만 등록하면 같은 규격으로 참여합니다.
> **핵심은 에이전트가 아니라 구성(기록·목차·검수·CI)에 있습니다.** 성능은 에이전트마다 다르겠지만, 맥락이 끊기지 않고 서로의 작업을 이어받는 힘은 구성에서 나옵니다.

---

## 1. 왜 필요한가

| 에이전트끼리 일할 때 생기는 문제 | AGS의 답 |
|---|---|
| 세션이 바뀌면 계획·진행 상황을 잃음 (에이전트 전용 메모리는 이어지지 않음) | 기록의 원본은 **레포 안 `worklog/`** |
| 기록이 쌓일수록 무거워지고 엉뚱한 추론이 늘어남 | 타임라인·인덱스·목차로 정리해서 **필요한 조각만** 불러옴 (컨텍스트 팩) |
| 다른 에이전트가 무엇을 하는지 모르고 같은 일을 하거나 충돌함 | `NOW.md` 작업판 잠금, 작업 키(`work`)로 중복 차단 |
| "완료"라고 했는데 검증이 없음, 하드코딩이 실제 기능처럼 보임 | 워크스루 증적·평가·배드 케이스, 구현 상태 표기(v1.2) |
| 규칙이 레포마다 흩어지고 지켜지는지 모름 | 하나의 공개 원본 + 검수 키 + CI로 **자동 확인** |

## 2. 구성 (3선)

```
            ┌───────────────────────────────────────────┐
            │  AGS-SPEC  공개 저장소 (이곳) · 버전 태그  │  ← 유일한 원본
            └──────────────┬──────────────┬─────────────┘
                 ① 행동     │      ② 도구   │      ③ 강제
        ┌───────────────────┘              │             └──────────────┐
   AGS-GR (글로벌 룰)                  AGS-KIT (검수 키)            AGS-CI (공통 CI)
   각 에이전트 전역 규칙에 설치        레포 .agentkit/ 에 설치       레포 워크플로
   → 어느 레포를 열든 자동 적용        context · check · doctor     push·PR마다 🔴면 실패
                 │                         │                          │
                 └──────────────┬──────────┴──────────────────────────┘
                                ▼
                 각 레포의 worklog/  (NOW · INDEX · BADCASES · tasks …)
                 ← AGS-RS(레포 세션)들이 여기서 소통하며 함께 작업
```

| 선 | 무엇 | 퍼지는 방법 | 통제 |
|---|---|---|---|
| ① 행동 | **AGS-GR** 글로벌 룰 | 각 PC의 에이전트 전역 규칙 파일에 요약본 설치 | 에이전트마다 자기 파일만 |
| ② 도구 | **AGS-KIT** 검수 키 | 레포에 한 번 설치, 이후 버전 갱신 | 태그 발행 = 참여 HQ 합의 + 소유자 승인 |
| ③ 강제 | **AGS-CI** | 레포 워크플로가 키로 계약 점검 | 레포는 버전만 따라감 |

- **AGS-HQ**(에이전트별 관리 본부)는 규격을 관리하고 레포를 **관측만** 합니다. 레포 파일은 고치지 않습니다.
- 실제 개발과 기록은 **AGS-RS**(레포 세션)가 합니다.
- 레포 안에 원래 있던 "HQ", "팀" 같은 말은 그 레포의 용어로 그대로 둡니다. AGS 문서는 `AGS-` 명칭만 씁니다 → [TERMS.md](TERMS.md)

## 3. 레포에 생기는 것

```
<레포>/
├─ .agentkit/agentkit.py            AGS-KIT
├─ .github/workflows/agent-contract.yml   AGS-CI
└─ worklog/
   ├─ NOW.md          지금 상태 + 작업 중 에이전트 (잠금)
   ├─ INDEX.md        작업 타임라인 (1작업 1줄)
   ├─ BADCASES.md     배드 케이스 타임라인 (교훈)
   └─ tasks/YYYY-MM/<TaskID>_<slug>.md   작업 1건 = 파일 1개 (계획 → 체크리스트 → 워크스루 → 인수인계 → 평가)
```
- v1.2: `IMPLEMENTATION.md`(하드코딩·미구현, `IMP-` 번호), `DEFECTS.md`(결함, `DEF-` 번호)

## 4. 에이전트의 하루 (모든 에이전트 공통)

| 시점 | 하는 일 | 키 명령 |
|---|---|---|
| 세션 시작 | 컨텍스트 팩만 읽는다 (NOW + 최근 INDEX + 진행 중 Task 요약 + 최근 배드 케이스) | `context` |
| 작업 시작 | 겹치지 않는 Task ID, 작업판에 내 줄, P0·P1은 계획을 사람에게 확정받음 | `new-id` |
| 진행 중 | 보고하기 전에 기록부터 | — |
| 끝 | 워크스루(실제 검증) + 인수인계 + 평가 → 점검 → 코드와 기록을 한 커밋에 | `check` |
| 다음 세션 | 다른 에이전트라도 컨텍스트 팩만으로 이어받는다 | `context` |

## 5. 새 에이전트를 참여시키려면

1. [TERMS.md](TERMS.md)의 에이전트 코드 표에 두 글자 코드를 등록합니다 (현재 `CL`, `AG`, `US`. v1.2부터 임의 코드 등록제).
2. [global/](global/) 요약본을 그 에이전트의 전역 규칙 파일에 설치하고 `<REPOS_ROOT>`를 바꿉니다.
3. `agentkit.py hash <전역 규칙 파일>`로 설치 버전을 보고합니다.
